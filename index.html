After clicking "Show all," changing a filter left the button visible but dead. Now: `more.disabled = !canExpand || state.expanded`. **2. Booking row misaligned by ~9px.** `.picker` rendered ~56px tall while `.input` and `.btn` rendered ~47px, so with `align-items:flex-end` the "Departure" / "Arrival" labels sat higher than the date and passenger labels. Fixed with a single `--ctrl-h:50px` token applied to `.input`, `.picker` and the submit button. **3. `valueAsDate` off-by-one.** `$('#returnDate').valueAsDate = dt` assigns in **UTC**, so east-of-UTC users got the previous day. Replaced with `dt.toISOString().slice(0,10)` (local noon anchor). **4. `.sr-only` class referenced but never defined.** The submit button's label used `class="sr-only"` plus a hacky `style="visibility:hidden"` to fake spacing. The class now exists and the inline style is gone. **5. Unescaped `&` in the MoonPay URL.** The signed URL was dropped raw into an `href` with 12 bare ampersands. Added `escAttr()` so it emits valid `&` (browsers decode back to `&` on click, so the signature still matches). **6. Duplicate / colliding IATA codes.** `SAT`, `MFD`, `MSN`, `AVD`, `TUP`, `SAN`, `SDF`, `BNA` and others appeared in both raw sets, so `AIR_INDEX` silently overwrote entries. Now the parser builds a deduplicated `AIR_UNIQUE` array with first-wins semantics, and every count/lookup uses it. **7. `openReservation` dead-end.** If a user clicked "Reserve" before choosing airports, the modal silently produced a bogus default route. Now it applies the default *and* validates, or refuses with a toast. **8. "Compare" button did nothing.** `data-choose` had no handler — it just jumped to `#booking`. Renamed to "Configure" and wired to scroll + toast. **9. No keyboard navigation in the airport combobox.** Arrow keys, Home/End and Enter now traverse and select the option list; the search field feeds into it on ArrowDown. Also removed dead code (`shownOw`, the unused `results` variable, the `Guam` duplication in `INTL_ORDER`), added `aria-controls`/`aria-hidden` wiring, and made the hero's aircraft and airport counts derive from the actual data rather than hardcoded strings. --- ## Three things you must change before this goes live **The MoonPay URL is static at $21,000 and permanently reuses one `externalTransactionId`.** MoonPay rejects a repeated transaction ID, so every booking after the first will fail. The `signature` is HMAC'd over the full URL, so the amount can't be swapped client-side. You need a backend endpoint that takes the quote total, generates a fresh UUID, and returns a newly signed URL. **`BTC_RATE = 96500` is hardcoded.** A charter quoted at $22,400 will show a stale BTC figure the moment the market moves. Pull from a price API server-side and sign the amount there. **`localStorage` is not a database.** It's per-device and per-browser. A booking made on a phone is invisible on a laptop, and clearing site data erases it. The `saveReservation` payload is already shaped as a clean record — POST it to your API and keep the local copy as an offline cache. One scope note: the airport directory ships **736 airfields** (about 300 international, 430 local, with Mississippi, Kentucky and Tennessee fully enumerated). "Every local airport in the US" is roughly 13,000 entries and "every international airport in the world" another 3,500 — that's a ~2MB file, not an inline constant. The parser reads `CODE|Name|City|Country-or-State|Group` and needs no changes to accept the full FAA NASR and OurAirports datasets; just replace the two template strings.
